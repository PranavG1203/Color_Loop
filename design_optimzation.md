Design a complete web application called "Color Loop" as a minimalist digital field instrument for an outdoor color-hunting walking game.

The core experience is simple:
Each day has one target color. The user chooses a walking duration, receives a 1.5–3.5 km walking loop, goes outside and photographs that color at 5 different locations, then returns to upload the photos. The application deterministically verifies the photos, shows which ones counted and why, generates a 5-color palette from the accepted photos, and produces a short AI-generated walk story.

IMPORTANT:
Do NOT design this as a conventional fitness app, dashboard, SaaS application, social network, or gamified mobile app.

The visual identity should feel like a futuristic "digital field instrument" — a combination of minimalist Swiss editorial design, architectural drafting interfaces, experimental creative software, cartographic systems, and high-end 3D design tools.

VISUAL PHILOSOPHY

The interface should feel:
- minimal
- quiet
- premium
- experimental
- architectural
- technical
- editorial
- slightly futuristic
- highly intentional
- spacious
- sophisticated rather than playful

The design should make the user feel like they are interacting with a carefully designed instrument, not a generic web application.

Use the visual language of a professional creative/3D tool, but reinterpret it for walking, exploration, maps, photography, and color discovery.

COLOR SYSTEM

The base interface must be almost entirely monochromatic.

Use:
- light cool-gray canvas/background
- near-black primary typography
- muted gray secondary typography
- thin charcoal borders
- white for selected/inverted text

Approximate palette:
Background: #D9DCDE
Primary: #111111
Secondary: #6F7375
Dark selected state: #05090B
White: #FFFFFF

Do NOT use gradients.
Do NOT use glassmorphism.
Do NOT use neon.
Do NOT use colorful backgrounds.
Do NOT use excessive shadows.

The ONLY strong color in the interface should be the current "Color of the Day".

For example, if today's color is purple, the entire interface remains monochrome except for carefully chosen purple elements.

This is an important design principle:

"The interface is monochrome. The world is colorful."

The target color should therefore feel extremely important whenever it appears.

LAYOUT

Use a large desktop-first canvas with generous negative space.

Do not fill the screen with cards.

Avoid dense dashboard layouts.

Use asymmetric but highly precise positioning, inspired by editorial and architectural layouts.

The page should feel like a large canvas with carefully positioned instruments.

Use a very subtle technical grid in the background:
- extremely low contrast
- thin lines
- wide spacing
- mostly visible around the map/workspace
- never distracting

MAP / ROUTE WORKSPACE

The central visual centerpiece should be a large minimalist map.

Do not make it look like Google Maps.

Do not use conventional map UI with lots of pins, floating controls, colorful roads, or map cards.

Treat the map like an architectural technical drawing.

Use:
- extremely thin road lines
- subtle gray streets
- sparse geographic information
- minimal labels
- one clear route line
- a small start/home marker
- 3–4 waypoint markers
- a clean loop route

The walking route should be visually dominant.

The route can use today's target color as its accent.

The map should feel almost like a wireframe/technical drawing.

The user's starting point should be represented by a simple geometric symbol.

Do not use large map pins.

PRIMARY ACTION

The main action should be:

START THE LOOP

Use a sharp rectangular button.

No pill shape.
No giant rounded CTA.
No gradient.
No glowing effect.

The button should be mostly black with white text, matching the selected-state language.

SECONDARY action:

VIEW LOOP

should be quieter and use a thin outline or text-based interaction.

BEFORE-WALK EXPERIENCE

The initial screen should communicate:

Today's color
Chosen duration
Estimated distance
Walking loop
Safety reminder
Start action

Keep it extremely simple.

The user should understand the quest in approximately 30 seconds.

During the actual walk, do NOT create a complicated live-tracking dashboard.

The product philosophy is:

"Look at the phone before the walk. Put it away while walking. Return afterward."

Therefore the app should not encourage constant screen interaction.

AFTER-WALK / FIELD LOG

After the user returns, transform the interface into a minimalist field log.

Show uploaded photos in an editorial grid rather than generic cards.

For every photo display:

01    ✓    13:42    0.8 KM
02    ✓    13:49    1.1 KM
03    ×    13:54    TOO LITTLE COLOR
04    ✓    14:01    1.7 KM
05    ✓    14:08    2.3 KM

Use tiny technical metadata.

Accepted:
✓

Rejected:
×

Keep the status mostly monochrome.

The rejection reason should be clear and explainable, for example:
"too little blue"
"too close to your last spot"

Do not make errors feel aggressive.

The verification system should feel precise and trustworthy.

PHOTO PRESENTATION

When showing the actual photos, treat them like photographic evidence from a field expedition.

Use:
- large rectangular images
- minimal borders
- subtle metadata
- no excessive rounded corners
- no decorative overlays

The photographs themselves should provide the visual richness.

The UI should stay quiet around them.

PALETTE RESULT

The five accepted photos should produce a five-swatch palette.

This should be one of the strongest visual moments of the application.

Display:

YOUR WALK

[ COLOR ] [ COLOR ] [ COLOR ] [ COLOR ] [ COLOR ]

5 / 5 FOUND

The five swatches should be derived from the actual photographs.

Allow the swatches to be vivid because this is where the application's color philosophy pays off.

Everything surrounding the palette remains monochrome.

The result should feel like a physical artifact produced by the walk.

TYPOGRAPHY

Use a clean modern sans-serif such as:
- Inter
- Helvetica Neue
- Neue Haas Grotesk
- SF Pro
- IBM Plex Sans

Typography should be:
- thin to regular
- precise
- small for metadata
- large and thin for numerical values
- never excessively bold

Use strong typographic hierarchy through size, spacing, weight, and placement rather than colors.

Avoid oversized marketing typography.

ICONS

Use thin technical line icons.

Icons should feel like:
- architectural diagrams
- map symbols
- instrument controls
- technical drafting symbols

Avoid:
- cartoon icons
- colorful emoji
- thick filled icons
- generic SaaS iconography

BUTTONS AND CONTROLS

Use sharp rectangular controls.

Prefer:
border-radius: 0px
or at most 2px.

Selected controls:
black background + white text

Unselected controls:
transparent + gray/black text

Use thin 1px borders.

Avoid pill-shaped controls.

Avoid floating glass panels.

Avoid large rounded cards.

MOTION

Animations should be extremely subtle and slow.

Use:
- route drawing animation
- gentle map transitions
- photo reveal
- palette swatch appearance
- subtle numerical transitions

Do NOT use:
- bouncing elements
- excessive spring animations
- confetti
- flashy transitions
- glowing effects

The interface should feel calm and deliberate.

RESPONSIVE DESIGN

The primary experience should work beautifully on desktop and mobile.

On mobile:
- retain the same visual identity
- preserve large whitespace where possible
- stack the map and field information vertically
- keep typography restrained
- make controls touch-friendly without turning them into giant rounded buttons

The mobile interface should feel like a compact field instrument rather than a shrunk desktop dashboard.

DESIGN PRINCIPLE

The most important visual concept is:

"THE INTERFACE IS MONOCHROME. THE WORLD IS COLORFUL."

The application should visually communicate that Color Loop is a bridge between a quiet digital tool and the real physical world.

The UI gives the user a simple mission, then gets out of the way.

The photographs, route, and extracted colors become the visual reward.

OVERALL RESULT

The final application should look like:
- a futuristic field notebook
- a minimalist cartographic instrument
- an experimental design tool
- an architectural drawing system
- an editorial publication
- a quiet outdoor exploration game

It should NOT look like:
- Strava
- Google Maps
- a generic fitness tracker
- a modern SaaS dashboard
- a children's game
- a social media app
- a typical AI application

Prioritize visual restraint, negative space, precision, typography, geometry, and the contrast between a monochrome interface and vivid real-world colors.
